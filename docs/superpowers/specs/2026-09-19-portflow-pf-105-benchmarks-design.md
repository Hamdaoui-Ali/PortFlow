# PF-105 Reproducible Engine Benchmarks

**Status:** Draft for review  
**Date:** 2026-09-19  
**Parent slice:** PF-104 engineering observability  
**Scope decision:** Local reproducible performance evidence

## Goal

Add a local benchmark harness that runs one deterministic Parquet workload
through DuckDB, Polars, and PySpark, verifies that every engine produces the
same canonical result, and writes a machine-readable comparison report with
the environment and measurement protocol attached.

PF-105 is an engineering evidence tool. It is not a public product feature,
not a production workload, and not an optimization mandate based on one
developer machine's timings.

## Intended outcome

The repository owner should be able to answer:

- Which engine completed the shared workload fastest on this machine?
- Did every engine produce the same result as the PortFlow telemetry contract?
- What fixture size, engine version, runtime, and environment produced the
  measurement?
- Can the run be repeated later without changing the public snapshot or the
  normal CI dependency set?

The report is evidence, not a universal ranking. Timings are compared only
within a report generated by the same workload protocol and environment.

## Approved decisions

- Use one deterministic synthetic telemetry fixture with the same field names
  and value rules as `TelemetryEvent`.
- Use one engine-neutral aggregation workload that reads Parquet, filters a
  UTC time window, groups by terminal and equipment state, and computes counts
  and numeric averages.
- Normalize and hash the sorted result so DuckDB, Polars, and PySpark must
  agree before timings are treated as valid evidence.
- Run DuckDB and Polars through the existing Python environment.
- Run PySpark through a separately pinned local runner so PySpark and its JVM
  do not enter the main PortFlow runtime or default CI installation.
- Measure one warm-up plus three timed repetitions per engine by default, and
  report median and p95 elapsed time, rows per second, fixture bytes, and
  engine startup time separately.
- Keep full benchmark runs explicit and local. CI may run a small DuckDB/Polars
  contract smoke test, but timing thresholds must not gate ordinary CI.
- Write generated fixtures and reports below ignored benchmark-artifact paths;
  commit the harness, workload contract, tests, and runbook only.
- Preserve the public static product, existing pipeline contracts, streaming
  behavior, and PF-104 observability behavior unchanged.

## Non-goals

- No public UI, dashboard, route, snapshot field, or Pages artifact.
- No change to the existing Gold SQL or KPI definitions.
- No automatic tuning, query-plan rewriting, or engine-specific production
  implementation.
- No mandatory PySpark installation for PortFlow contributors or CI jobs.
- No cloud benchmark, managed Spark cluster, BigQuery lab, or Databricks lab.
- No committed timing baseline that treats one host's numbers as universal.
- No benchmark execution during the default `docker compose up`, pipeline
  runner, streaming runner, or public snapshot generation.

## Architecture

```text
deterministic fixture generator
            |
            v
shared Parquet fixture + SHA-256
       /         |          \
      v          v           v
  DuckDB      Polars      PySpark runner
      \          |           /
       v         v          v
   canonical sorted result + result hash
                 |
                 v
      JSON comparison report + metadata
```

The benchmark package owns orchestration, fixture metadata, canonical result
normalization, timing aggregation, and report validation. Each engine adapter
owns only the execution of the same workload and returns rows in the shared
result shape. The PySpark adapter is a process/container boundary, not a
dependency imported by the main PortFlow package.

### Benchmark package boundary

Create a focused repository-local `benchmarks/portflow_benchmarks/` package
rather than adding benchmark concerns to `src/portflow/`. It is invoked from
the repository root as `python -m benchmarks.portflow_benchmarks` and is not
included in the PortFlow wheel. The package may import the already installed
DuckDB and Polars libraries, but production modules must not import it. Its
public CLI should support:

```text
python -m benchmarks.portflow_benchmarks run
python -m benchmarks.portflow_benchmarks verify
```

The `run` command accepts explicit fixture row count, repetitions, warm-ups,
engine selection, fixture directory, and report path. Defaults must be small
enough for a smoke run and must never silently create the largest fixture.
The `verify` command checks fixture determinism, result equivalence, report
schema, and that all requested engines completed successfully.

### Fixture contract

The generator writes a deterministic Parquet dataset with these columns:

| Column | Contract |
| --- | --- |
| `event_id` | Stable `evt-<six digits>-<six digits>` identifier |
| `equipment_id` | Stable equipment identifier matching `TelemetryEvent` |
| `terminal_id` | Stable `TM-<three digits>` identifier |
| `event_timestamp` | UTC timestamp at a fixed five-minute cadence |
| `state` | One of the existing equipment states |
| `available` | Boolean consistent with `state` |
| `load_percent` | Deterministic value in `[0, 100]` |
| `temperature_c` | Deterministic value in `[-20, 150]` |

The fixture seed, row count, schema, generator version, Parquet compression,
and relative file layout are report fields. The same seed and row count must
produce identical logical rows and logical fixture hash on repeated runs. The
implementation may split the fixture into deterministic files for larger
sizes, but the file ordering must not affect the logical hash. Physical file
bytes and their size remain useful environment evidence but are not the
cross-engine correctness identity.

### Workload contract

Each adapter must execute the equivalent of:

```sql
SELECT
  terminal_id,
  state,
  COUNT(*) AS event_count,
  SUM(CASE WHEN available THEN 1 ELSE 0 END) AS available_event_count,
  ROUND(AVG(load_percent), 6) AS average_load_percent,
  ROUND(AVG(temperature_c), 6) AS average_temperature_c
FROM telemetry_fixture
WHERE event_timestamp >= :window_start
  AND event_timestamp < :window_end
GROUP BY terminal_id, state
ORDER BY terminal_id, state
```

Adapters may express this with SQL or dataframe operations, but they may not
change the filter window, grouping keys, null policy, rounding precision, or
sort order. The canonicalizer serializes values with stable field order,
UTC timestamps, explicit integer/float handling, and a terminating newline;
the SHA-256 result hash is the correctness gate.

### PySpark isolation

The PySpark runner must use a committed configuration with a pinned Spark
image digest or exact immutable image reference. It receives the same fixture
mount and workload parameters as the host adapters and writes a bounded JSON
result to an artifact mount. The default PortFlow Python environment must not
import `pyspark`, and the default Compose services must not start Spark.

If Docker or the pinned Spark runner is unavailable, DuckDB/Polars evidence
may still be generated, but the report must mark PySpark as unavailable rather
than silently omitting it from an all-engine comparison. A full comparison is
valid only when all selected engines have matching result hashes.

## Report contract

Each report is JSON with a versioned top-level schema:

```json
{
  "schema_version": 1,
  "fixture": {
    "seed": 42,
    "rows": 100000,
    "logical_sha256": "...",
    "bytes": 0,
    "generator_version": "1"
  },
  "workload": {
    "name": "telemetry_terminal_state_summary",
    "window_start": "2026-01-01T00:00:00Z",
    "window_end": "2026-02-01T00:00:00Z",
    "result_rows": 0,
    "result_sha256": "..."
  },
  "environment": {
    "git_sha": "...",
    "platform": "...",
    "python": "..."
  },
  "engines": [
    {
      "name": "duckdb",
      "version": "...",
      "startup_seconds": 0.0,
      "warmup_seconds": 0.0,
      "timed_seconds": [0.0, 0.0, 0.0],
      "median_seconds": 0.0,
      "p95_seconds": 0.0,
      "rows_per_second": 0.0,
      "result_sha256": "...",
      "status": "ok"
    }
  ]
}
```

The exact report schema is validated by tests. It must not contain raw
payloads, arbitrary exception text, machine secrets, absolute paths, or
unbounded per-row labels. Failed or unavailable engines retain a bounded
status and a short reason code; the report remains safe to share as local
engineering evidence.

## Artifacts and repository boundaries

- Generated fixtures: `.benchmarks/fixtures/`.
- Generated reports: `.benchmarks/reports/`.
- Temporary PySpark exchange files: `.benchmarks/spark/`.
- All three paths are ignored and are never read by the public exporter or
  copied into `web/public/data`.
- The runbook documents cleanup by removing only `.benchmarks/`.
- Existing `web/public/data` hashes must remain unchanged after benchmark
  generation and verification.

## Testing and verification

Before PF-105 is complete:

- unit tests cover deterministic fixture generation, schema validation,
  canonical result hashing, report validation, timing aggregation, and
  bounded failure states;
- an integration smoke test runs the shared workload through DuckDB and
  Polars and asserts identical result hashes;
- a PySpark contract test runs only when the pinned local runner is available
  and otherwise records an explicit skip;
- configuration tests verify the Spark image pin, read-only fixture mount,
  artifact boundary, and that default Compose has no benchmark service;
- the runbook documents small, medium, and large fixture profiles, commands,
  required Docker/JVM conditions, expected artifacts, and cleanup;
- Ruff, mypy, the full existing Python suite, and the benchmark contract tests
  pass; and
- `web/public/data` is byte-for-byte unchanged.

## Rollout and follow-up

PF-105 remains local, explicit, and disposable. It provides comparable
evidence for future engineering choices without turning benchmark numbers into
production SLOs. Cloud portability experiments belong to PF-106 and PF-107
and must not be folded into this slice.
